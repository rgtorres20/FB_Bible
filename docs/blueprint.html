Productization plan — step by step

What survives: the IA — tabs, feed budgets, trust tiers, per-league ranking. This page is the PRD.
0Player IDs — the foundation
One canonical record per player — {id, name, team, pos} — and every list (Alerts, Board, Sleepers, Intel, FFBets) references the ID instead of repeating name strings. Use Sleeper's player IDs so Phase 1 joins for free.
Fixes: silent name-mismatch breaks · Effort: in-app, no backend · Do now
1Live sync — Sleeper API
Wire the Sync button to api.sleeper.app — free, no key, browser-reachable: injury status per player, trending adds/drops, player metadata. Sync button becomes real for the fast feeds; Data health stamps become true timestamps.
Fixes: fake sync, stale metrics · Effort: in-app, no backend · Do next
2Yahoo league link
OAuth to the Yahoo Fantasy API: live rosters, draft results, opponent picks for f1/192426 and f1/811739. Needs a small server (token exchange) — first piece that leaves the browser.
Fixes: manual roster/pick entry · Status: built — repo FB_Bible, awaiting deploy + Yahoo credentials
3Scheduled jobs + notifications
Move the sync spine server-side: cron jobs poll the feeds on their budget intervals, write to a database, and the Settings push rules ("out for season → push immediately") finally deliver via web push. The Pickup Queue runs here overnight: push the instant a trigger fires — or execute the add/drop itself with a Yahoo write-scope upgrade (fspt-w). That retires the 2 AM wake-up.
Fixes: manual chat pulls, dead push rules · Effort: real backend · After Yahoo
4Real projections & salaries
Replace model estimates in FFBets and Team intel with a sourced feed (SportsDataIO / MySportsFeeds / DK sheet import). Until then every estimate stays labeled as one.
Fixes: hand-set numbers · Effort: data feed + import · Last
5Structure — split the monolith
Data moves out of the page into JSON files (players, alerts, board, meta) the app loads at startup — syncs then touch data, not code. Leagues and roster shape become config, not constants.
Fixes: 2,400-line single file · Effort: refactor, in-app · Alongside 0–1
6Platforms — web, iPhone, Android
PWA-first: one web app, installable to the home screen on iOS and Android (manifest + service worker — offline board, cached feeds). Web push covers the Phase 3 alerts on all three (iOS 16.4+ requires the app be installed). Native wrappers (Capacitor) only if store presence or richer notifications ever matter — same codebase either way.
Fixes: desktop-only access · Status: built — manifest + sw.js + icons in project; activates on any https deploy
7Obsidian — the design notebook
A vault as the project's thinking space: this blueprint, CLAUDE.md and the phase specs exported as markdown notes; scouting notes and draft-day tier sheets written in Obsidian and linked player-by-player. The vault syncs to the repo (it's just .md files in a folder), so notes travel with the code and feed back into syncs.
Fixes: design decisions scattered across chats · Effort: export + folder convention · Anytime
8AI assistant — "Ask the Bible"
A question panel grounded in the app's own data — board, sleepers, live wire, league scoring — not generic advice. In the design preview it calls Claude built-in and free; deployed, the Phase 2/3 server proxies the AI call (browser pages can't hold a key). Candidates: Claude / OpenAI APIs (per-call), Gemini (free tier). Copilot has no consumer API.
Status: parked — design settled, not built · Effort: one panel + server proxy at deploy · When ready
